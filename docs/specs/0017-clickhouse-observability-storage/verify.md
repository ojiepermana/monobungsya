# 0017. Verification plan

Run verification against the exact ClickHouse patch and production hardware profile recorded by the implementation. Do not use Docker or Docker Compose.

Evidence carried over from the earlier hybrid revision is kept where the check and its acceptance criterion did not change. Checks that only existed to prove dual write, backfill, promotion, or cutover are removed, not marked passed.

## Static and contract checks

* [x] Run repository typecheck, lint, dependency, observability, OpenAPI, generated SDK, and progress checks. Prove producers only depend on the four method `ObservabilitySignalStore` interface and Audit Trail does not import it. Covers **AC-1**, **AC-3**, **AC-4**, and **AC-23**.
* [ ] Run the adapter contract suite against the fake and the ClickHouse adapter only. Prove accepted or dropped results, bounded flush, bounded shutdown, diagnostics, retry identity, and unchanged business exceptions. Prove the suite no longer has a PostgreSQL adapter to run against. Covers **AC-4**, **AC-8**, and **AC-9**. The earlier run passed against fake, PostgreSQL, and ClickHouse adapters; it must be re-run once the PostgreSQL adapter is deleted.
* [ ] Search the repository for the removed machinery. Prove there is no `postgres.ts` Signal adapter, no `backfill*`, no `promotion*`, no dual target in `store.ts`, `configured.ts`, or `runtime.ts`, no `readMode` or `writeMode` in `packages/config` or either logs repository, and no `observability:promotion:record`, `observability:promotion:activate`, `observability:postgres:legacy-write-policy`, `observability:backfill`, or `observability:postgres:adapter-contract` script. Covers **AC-4** and **AC-22**.
* [ ] Run carried telemetry, propagation, sampling, metric aggregation, Elysia lifecycle, benchmark, baseline, ingestion, alert, and permission suites. Compare benchmark overhead with the accepted gates. Covers **AC-1**, **AC-2**, and **AC-13**. The repository suites pass, and the latest local benchmark completed with complete telemetry (25,000 observations, zero drops), but the compatible baseline comparison is `fail`: driver CPU `+21.7%`, RSS `+43.8%`, heap `+39.1%`, and throughput `-19.0%`. A same-host replay from the pre-hybrid commit produced approximately `7.65s` CPU and `760k/s`, matching the hybrid run and diverging from the approved artifact (`6.22s`, `944k/s`); this indicates baseline drift or runner-load variance. A 27-report local calibration attempt was rejected because fewer than 20 robust Tukey inliers remained; a full 20-run attempt had 18 valid reports, with one CV `20.1%` failure and one event-loop p95 `>10 ms` failure. The contract's official 20-run calibration on a controlled runner is still required. The microbenchmark remains diagnostic, so this is recorded as an open acceptance gate rather than a false pass.
* [ ] Run the official 20 run baseline calibration on a controlled runner. Prove at least 20 robust Tukey inliers, every metric coefficient of variation within the limit, and event loop `p95` within the limit, then compare instrumentation overhead against that new baseline. Covers **AC-2**.

## Startup gate checks

* [ ] Present a wrong binary version, a missing `observability` database, a drifted table schema version, and an invalid async setting. Prove the process refuses to start with a failing exit code and a message naming the failed check, and prove no Blind Spot is reported because no process is serving. Covers **AC-20**. * [ ] Stop ClickHouse entirely and start every backend. Prove each process starts, stays ready, serves business traffic, reports Signal store `blind_spot` with a sanitized reason, and fails the separate deployment verification and benchmark readiness. Covers **AC-16** and **AC-20**.
* [ ] Restart a backend while ClickHouse is down, then bring ClickHouse up. Prove the restart succeeds, no rolling restart is blocked, and the first successful ACK clears `blindSpotSince`. Covers **AC-20**.
* [ ] Set each removed variable in turn: `OBSERVABILITY_SIGNAL_WRITE_MODE`, `OBSERVABILITY_SIGNAL_READ_MODE`, `OBSERVABILITY_SIGNAL_PROMOTION_REPORT_ID`, `OBSERVABILITY_TELEMETRY_MIGRATION_URL`, `OBSERVABILITY_LOGS_MIGRATION_URL`, and `OBSERVABILITY_MIGRATION_LOGIN`. Prove config parsing fails, the message names the variable and states it was removed, and no process starts believing a storage mode is active. Covers **AC-22**.
* [ ] Run with `ENABLE_INFRASTRUCTURE=false`. Prove the Signal store is `disabled` without contacting ClickHouse and no startup failure is raised. Covers **AC-20** and **AC-23**.

## Writer and failure checks

* [x] Send Span, Metric Bucket, Application Log, and Access Log through real HTTP inserts with `async_insert=1` and `wait_for_async_insert=1`. Prove only disk flush ACK increments written count and a retry uses identical row content, write version, and insert token. Covers **AC-5**, **AC-8**, and **AC-9**.
* [x] Fill item and byte queue caps independently. Prove 20 percent priority reserve retains error, slow, and access failure Signal before low priority data, no kind starves, memory stays bounded, and every drop reason is counted. Covers **AC-8**, **AC-9**, and **AC-10**. Local bounded-store runs filled item capacity (8 normal rows plus 4 priority rows at a 10-item cap), retained all priority rows, and recorded three `queue_full` drops; a separate 40-item round-robin run delivered five batches of every Signal kind with no starvation. The byte-cap eviction test retained priority data and recorded `queue_full`; queue depth/bytes remained bounded.
* [x] Inject network failure, timeout, 429, 5xx, authentication failure, schema failure, one poison row, and shutdown timeout. Prove three retries maximum, recursive isolation, sanitized diagnostic, accurate Blind Spot start, and unchanged request, transaction, message, job, and process result. Covers **AC-7**, **AC-9**, and **AC-18**.
* [x] Send expired, future skewed, malformed, and over 4 KiB Signal. Prove they are rejected before network write with stable diagnostic and monotonic duration remains unchanged by wall clock skew. Covers **AC-7**.
* [ ] Inspect `diagnostics()`. Prove it reports one set of counters with no per target map, and that `written` means a ClickHouse disk flush ACK. Covers **AC-4** and **AC-16**.

## Read and control checks

* [x] Query every allowed time preset and maximum custom range. Prove Span rejects over seven days, other Signal rejects over 30 days, options use the same scope, and missing Metric Bucket renders a gap. Covers **AC-11** and **AC-13**. Local pinned ClickHouse HTTP matrix returned 200 for 15 minute, 1 hour, 6 hour, 24 hour, 7 day, and 30 day bounded ranges, 422 for over retention, and nonzero missing bucket coverage.
* [x] Traverse at least three pages forward and two backward for Trace, Application Log, and Access Log. Prove stable row order, page sizes, null boundary cursors, no exact total, filter fingerprint rejection, and expired cursor 422. Prove Audit Trail paging and exact totals remain unchanged. Covers **AC-12**, **AC-13**, and **AC-14**. Local pinned ClickHouse HTTP fixtures returned 3 forward pages and 2 backward pages for all three Signal lists (Trace 50/50/20, logs 100/100/20), with available storage and correct boundary cursors; filter-bound cursor/invalid-range 422 behavior is covered by the focused route tests. The live run exposed and fixed a ClickHouse cursor type error caused by projecting timestamps through `toString` before keyset comparison.
* [x] Saturate eight query slots and exceed both hard deadlines. Prove immediate 429 with `Retry-After`, bounded ClickHouse cancellation, allowlisted fields, parameter binding, and no healthy empty response. Covers **AC-14** and **AC-15**. Reader tests occupy all eight slots and assert immediate `429`/`Retry-After: 1`; the same suite proves the 5-second (up to 24 hours) and 10-second (over 24 hours) budgets, shared subquery deadline exhaustion, read-only settings, and bound values. Both live log routes preserve the quota mapping.
* [x] Stop ClickHouse. Prove Signal list returns 200 with empty data plus `blind_spot`, Signal detail returns 503, expired detail returns 404 when storage is available, and PostgreSQL Control routes retain their own 503 semantics. Covers **AC-14**. With the pinned local server stopped, the live logs list returned 200/empty/`blind_spot` and the live trace detail returned 503 with `observability_storage_blind_spot`; PostgreSQL Control behavior remains covered by its route tests.
* [ ] Read every Signal list and detail route after the read branching is removed. Prove no route can reach a PostgreSQL Signal query, Audit Trail still reads PostgreSQL with exact totals, and generated OpenAPI plus SDK match the shipped shapes. Covers **AC-3**, **AC-12**, and **AC-13**.
* [x] Call storage health with no identity, wrong permission, one valid observability permission, and through the gateway. Prove 401, 403, sanitized success, and no gateway route respectively. Covers **AC-16** and **AC-18**.
* [x] Fail two 30 second health probes and recover three. Prove PostgreSQL availability alert pending, firing, then resolved, one idempotent notification per transition, ordinary metric alerts unknown during failure, and disk thresholds at 70, 80, and 90 percent. Covers **AC-17**.
* [ ] Attempt writer SELECT, reader INSERT, runtime DDL, plaintext production connection, and sensitive fixture ingestion. Prove each is denied or sanitized and query log access is operator only with seven day retention. Prove the HTTPS only guard now lives on the runtime adapter, since the backfill command that previously carried it is deleted. Covers **AC-18**. Live pinned-ClickHouse privilege checks denied writer `SELECT`, reader `INSERT`, writer runtime DDL, and both runtime identities' `system.query_log` access; the query log definition reports a seven-day TTL. Telemetry sanitizer tests prove sensitive attributes and payload text are omitted, and the full suite covers sanitized diagnostics.
